  <action>Run `npm run dev` (already started in Task 1), open the printed URL, and step through all 6 checks listed in how-to-verify below. Reply with "approved" or describe failures.</action>
  <what-built>
    The full Phase 4 deliverable is wired and running locally:

    - `<Plasma>` (`src/components/plasma/Plasma.tsx`) — pure OGL component, ported from `inspo.txt`, with StrictMode-hard cleanup (`WEBGL_lose_context.loseContext()`, canvas dimensions zeroed, DOM removal in correct order)
    - `<PlasmaFallback>` (`src/components/plasma/PlasmaFallback.tsx`) — CSS-only radial gradient with optional slow opacity pulse
    - `<HeroBackdrop>` (`src/components/plasma/HeroBackdrop.tsx`) — dispatcher reading `useDeviceCapabilities`, owning the ScrollTrigger mount decision, running the 250ms pre-unmount fade
    - `App.tsx` — placeholder hero section wrapping `<HeroBackdrop>` inside `<AnimationErrorBoundary>`, sized to `100vh` so scrolling past it triggers the unmount

    Dev server is running. The four ROADMAP Phase 4 success criteria are verifiable manually in DevTools.
  </what-built>
  <how-to-verify>
    Open the dev URL Task 1 printed (likely `http://localhost:5173/`) in a desktop browser (Chrome recommended — best DevTools coverage). Run all 6 checks below in order. Type "approved" only after all 6 pass.

    **Check 1 — Plasma renders full-bleed in #FF4500 with mouse warp (ROADMAP SC #1)**
    - You should see an orange Plasma shader filling the top of the page behind the "Phase 4 — Plasma test harness" text.
    - The base color should read as orange-red, NOT yellow, blue, or any other hue. (#FF4500 is "OrangeRed.")
    - Move the mouse around inside the hero section. The plasma should subtly warp/follow — not dramatic, just a hint of reactivity (CONTEXT.md: keep inspo's 0.0002 coefficient).
    - In DevTools → Performance → record 2 seconds while idle. Frame rate should stay near 60 FPS on a desktop machine (look for the green FPS line, no large red gaps).
    - PASS if: visible Plasma, orange-red hue, mouse warps subtly, FPS stable.

    **Check 2 — Scroll past hero unmounts Plasma (ROADMAP SC #2)**
    - Open DevTools → Elements panel. Find the `<section aria-label="Plasma test harness">` element. Expand it. You should see a `<canvas>` child (inside the HeroBackdrop container).
    - Slowly scroll DOWN past the hero. As the section's bottom passes the viewport top, watch the DOM tree.
    - PASS if: the `<canvas>` disappears from the DOM AFTER a brief ~250ms fade (you'll see the opacity transition first, then the canvas element vanishes — NOT opacity:0 with the canvas still present).
    - Also: open DevTools → Console. You may see a "WebGL: CONTEXT_LOST_WEBGL: loseContext" log — that's correct, that's our `loseContext()` cleanup firing.

    **Check 3 — Scroll back UP remounts Plasma**
    - With the hero already scrolled past, scroll back UP into the hero.
    - PASS if: the `<canvas>` reappears in the DOM and the orange Plasma is visible again. This proves the `onEnterBack` ScrollTrigger callback works and the component can be cleanly re-initialized.

    **Check 4 — prefers-reduced-motion fallback (ROADMAP SC #3, part a)**
    - DevTools → Command Palette (Cmd/Ctrl+Shift+P) → type "Show Rendering" → in the Rendering tab, find "Emulate CSS media feature prefers-reduced-motion" → set to "reduce".
    - Reload the page.
    - In the Elements panel, search for `<canvas` (Cmd/Ctrl+F inside the Elements panel) — there should be ZERO canvas elements in the hero section.
    - The hero should show the deep red-to-black radial gradient instead. No animation — it should be completely static.
    - PASS if: zero `<canvas>` in the hero, gradient visible, no opacity pulse animation.
    - Then unset the reduced-motion emulation back to "No emulation" and reload.

    **Check 5 — no-WebGL2 fallback with pulse (ROADMAP SC #3, part b)**
    - In DevTools Console, run:
      ```js
      // Force the no-WebGL2 path by stubbing getContext for 'webgl2'.
      const origGetContext = HTMLCanvasElement.prototype.getContext
      HTMLCanvasElement.prototype.getContext = function (type, ...args) {
        if (type === 'webgl2') return null
        return origGetContext.call(this, type, ...args)
      }
      ```
    - Reload the page.
    - The hero should now show the gradient — but THIS time with the slow opacity pulse animation (because `prefersReducedMotion` is false but `supportsWebGL2` is false).
    - Watch for ~10 seconds. You should see the gradient subtly brighten and dim on a ~7s cycle.
    - PASS if: zero `<canvas>` in the hero, gradient visible AND pulsing.
    - Then hard-reload (Cmd/Ctrl+Shift+R) to restore the original `getContext`.

    **Check 6 — StrictMode single live context (ROADMAP SC #4)**
    - In dev mode, React 19 StrictMode double-invokes effects on mount. We need to prove only ONE WebGL context is live after settle.
    - Open DevTools → Memory → "Take snapshot." After 1-2 seconds, take a second snapshot.
    - In the second snapshot, filter for `WebGLRenderingContext` or `WebGL2RenderingContext`. There should be EXACTLY ONE retained instance, not two or more.
    - Alternative quick check: in DevTools Console, run `document.querySelectorAll('canvas').length`. With the Phase 4 hero visible and the NoiseOverlay also using a canvas... actually NoiseOverlay uses an SVG data-URI per STATE.md decision [01-02], not a canvas. So the expected count is 1.
    - For HMR safety, reload the page 5 times. After the 5th reload, repeat the `querySelectorAll('canvas').length` check. It should still be 1, not 5 or more — proving the StrictMode mount/cleanup/mount loop is leak-free.
    - PASS if: snapshot shows exactly 1 live WebGL context, canvas count is 1 (not multiplied) after 5 reloads.

    **If all 6 checks PASS**: type "approved" — Phase 4 will close and the next pass will write the SUMMARY and stop the dev server.

    **If any check FAILS**: describe what you saw vs. what was expected. The orchestrator will run `/gsd:plan-phase 04 --gaps` to create a gap-closure plan.
  </how-to-verify>
  <resume-signal>Type "approved" if all 6 checks pass, or describe any failures so a gap-closure plan can address them.</resume-signal>

<task type="auto">
  <name>Task 2: Build the pure <Plasma> OGL component with StrictMode-hard cleanup</name>
  <files>src/components/plasma/Plasma.tsx</files>
  <action>
    Create `src/components/plasma/Plasma.tsx`. This component does ONE thing: mount a WebGL2 canvas filling its container, run the Plasma shader, clean up correctly on unmount. NO scroll logic. NO device capability checks. NO conditional rendering. The `<HeroBackdrop>` dispatcher in Plan 04-02 gates whether this component ever mounts.

    Implementation contract — follow RESEARCH.md §"Pattern 1: WebGL Lifecycle inside useEffect" exactly:

    1. **Props interface `PlasmaProps`** (locked defaults from CONTEXT.md):
       ```ts
       interface PlasmaProps {
         color?: string              // default '#FF4500'
         speed?: number              // default 0.35  (CONTEXT: ~0.3–0.4, inspo's 0.6 was too fast)
         direction?: 'forward'       // locked literal type 'forward' — no pingpong/reverse
         scale?: number              // default 1.1
         opacity?: number            // default 0.85
         mouseInteractive?: boolean  // default true; caller passes !isMobile
       }
       ```
       Direction is locked as the literal `'forward'` per CONTEXT.md — DO NOT widen the type to `'forward' | 'reverse' | 'pingpong'`. Strip any pingpong/reverse branching code from the inspo port — dead code in a hot rAF loop is mental overhead.

    2. **`hexToRgb` helper**: Port verbatim from `inspo.txt` (`const hexToRgb = (hex: string): [number, number, number] => ...`). See RESEARCH.md §"hexToRgb utility (PORT VERBATIM)". Falls back to `[1, 0.5, 0.2]` on invalid hex.

    3. **Render**: Returns a `<div ref={containerRef} style={{ position: 'absolute', inset: 0, width: '100%', height: '100%' }} aria-hidden="true" />`. The OGL canvas is appended to this div inside the effect — caller is responsible for giving the parent a positioned context.

    4. **Single `useEffect`** with dependency array `[color, speed, direction, scale, opacity, mouseInteractive]` — any prop change tears down and rebuilds GL. (Plan 04-02's `HeroBackdrop` passes stable primitives so this only fires on real mount/unmount.)

    5. **Inside the effect, in order**:
       a. Bail if `containerRef.current` is null.
       b. Create `new Renderer({ webgl: 2, alpha: true, antialias: false, dpr: Math.min(window.devicePixelRatio || 1, 2) })`. The DPR cap is CRITICAL — see PITFALLS Pitfall 3 (iPhone Pro = DPR 3 = 9× pixel work = thermal throttle in 30s).
       c. Grab `gl = renderer.gl` and `canvas = gl.canvas as HTMLCanvasElement`. Set `canvas.style.display = 'block'; canvas.style.width = '100%'; canvas.style.height = '100%';` and `container.appendChild(canvas)`.
       d. Create `geometry = new Triangle(gl)`, `program = new Program(gl, { vertex, fragment, uniforms: { ... } })` with the uniforms listed in RESEARCH.md §"Pattern 1". Note: `uSpeed: { value: speed * 0.4 }` — the inspo trick that maps the slider [0..1] into the actual shader range. `uDirection: { value: 1.0 }` (literal — always forward). `uMouseInteractive: { value: mouseInteractive ? 1.0 : 0.0 }`.
       e. Create `mesh = new Mesh(gl, { geometry, program })`.
       f. **ResizeObserver wiring**: `setSize()` reads `container.getBoundingClientRect()`, clamps `w/h` to `Math.max(1, ...)` to dodge `setSize(0,0)` crashes, calls `renderer.setSize(w, h)`, writes `gl.drawingBufferWidth` / `gl.drawingBufferHeight` into the `iResolution` Float32Array uniform in place (DO NOT reallocate the Float32Array — `program.uniforms.iResolution.value` is the same array reference across frames). Wrap in `new ResizeObserver(setSize)`, observe `container`, call `setSize()` once synchronously.
       g. **Container-scoped mouse listener** (NOT window-scoped — per CONTEXT.md): if `mouseInteractive`, declare `let handleMouseMove: ((e: MouseEvent) => void) | null = null` and attach a `mousemove` listener to `container` that writes `e.clientX - rect.left` / `e.clientY - rect.top` into the `uMouse` Float32Array in place. Store the listener reference so cleanup can remove it.
       h. **rAF loop**: `let raf = 0; const t0 = performance.now(); const loop = (t: number) => { program.uniforms.iTime.value = (t - t0) * 0.001; renderer.render({ scene: mesh }); raf = requestAnimationFrame(loop); }; raf = requestAnimationFrame(loop);`. The `iTime` cast may need `(program.uniforms.iTime as { value: number }).value = ...` to satisfy TS.

    6. **CRITICAL cleanup (return from useEffect)** — order matters, do NOT shuffle:
       a. `cancelAnimationFrame(raf)` — stop the loop FIRST so the next paint can't read freed GL.
       b. `ro.disconnect()` — stop ResizeObserver.
       c. `if (handleMouseMove) container.removeEventListener('mousemove', handleMouseMove)` — null-guard because mouseInteractive may have been false.
       d. **Lose GL context** via `gl.getExtension('WEBGL_lose_context')?.loseContext()`. Use optional chaining — not all browsers expose the extension. This is the StrictMode-hard fix from PITFALLS Pitfall 1 — without it, React 19's mount→cleanup→mount cycle leaks a context per cycle, hitting the browser's ~16-context cap after a few HMR reloads.
       e. **Zero the canvas dimensions** — `canvas.width = 0; canvas.height = 0` — forces iOS Safari to release the backing-store texture memory (PITFALLS Pitfall 1 — without this, repeated mount/unmount cycles crash mobile Safari tabs).
       f. **Remove the canvas from the DOM** — `try { if (canvas.parentNode === container) container.removeChild(canvas) } catch (err) { console.warn('[Plasma] cleanup: canvas removal failed:', err) }`. Guard with try/catch because in dev StrictMode the canvas may already be detached.

    7. **TypeScript strict**: this file must pass `npm run build` with no `any` casts beyond the documented `iTime` uniform cast. Use `as Float32Array` on `program.uniforms.iResolution.value` and `program.uniforms.uMouse.value` reads.

    Anti-patterns to AVOID (per RESEARCH §Anti-Patterns):
    - DO NOT wrap any of this in `useGSAP` — `useGSAP` only cleans up GSAP resources, not WebGL contexts.
    - DO NOT read `useDeviceCapabilities()` inside this component — the gate lives in `<HeroBackdrop>`.
    - DO NOT attach the mousemove listener to `window` — CONTEXT.md says container-scoped.
    - DO NOT reallocate Float32Array uniforms inside the rAF loop — write in place.
    - DO NOT import from `'gsap'` directly — this file doesn't need GSAP at all.

    No tests are required for this plan (Phase 7 may add Vitest later). The verification is the human browser checkpoint in Plan 04-03.
  </action>

    1. Create `src/components/plasma/PlasmaFallback.tsx`:

       ```tsx
       interface PlasmaFallbackProps {
         /**
          * If true, applies a slow opacity pulse (~7s ease-in-out infinite).
          * Caller (HeroBackdrop) passes false when prefersReducedMotion is true.
          */
         animated?: boolean
       }

       export function PlasmaFallback({ animated = false }: PlasmaFallbackProps) {
         return (
           <div
             aria-hidden="true"
             style={{
               position: 'absolute',
               inset: 0,
               background:
                 'radial-gradient(ellipse at 50% 45%, ' +
                 'rgba(255, 69, 0, 0.55) 0%, ' +
                 'rgba(180, 30, 0, 0.35) 25%, ' +
                 'rgba(80, 10, 0, 0.2) 55%, ' +
                 '#050505 90%)',
               animation: animated ? 'plasma-fallback-pulse 7s ease-in-out infinite' : undefined,
             }}
           />
         )
       }
       ```

       Why this exact gradient: CONTEXT.md mandates "multi-stop deep red-to-black radial gradient (#FF4500 → deep red → #050505) — atmospheric, not generic". The four stops are Claude's Discretion — values chosen to feel like the Plasma's natural color falloff (hot orange core fading through deep red into the brand black at the edges). Ellipse rather than circle better matches the wide-aspect hero. The 50% 45% center sits the hot spot slightly above middle, matching where the eye expects a horizon.

       Why opacity-only animation: anything that triggers layout/paint per frame (transform, filter, background-position) defeats the purpose of a "fallback" path. Opacity is GPU-composited — essentially free. See RESEARCH.md §"Pattern 2: Fallback Component".

       Why `animation: undefined` (not `'none'`): React strips undefined inline-style properties, producing no `animation` declaration at all. `'none'` would emit `animation: none` which is harmless but noisier in DevTools.

    2. Append the keyframes to `src/styles/index.css`. Use these exact frames (Claude's Discretion within CONTEXT.md bounds — 6–8s, opacity only):

       ```css
       @keyframes plasma-fallback-pulse {
         0%, 100% { opacity: 0.85; }
         50%      { opacity: 1; }
       }

       /* Honor system reduced-motion even if a caller forgot to gate `animated`. */
       @media (prefers-reduced-motion: reduce) {
         @keyframes plasma-fallback-pulse {
           0%, 100% { opacity: 0.85; }
           50%      { opacity: 0.85; }
         }
       }
       ```

       The media-query override is belt-and-suspenders defense — the dispatcher already passes `animated={false}` when `prefersReducedMotion`, but if a future caller forgets, the CSS still keeps the static gradient.

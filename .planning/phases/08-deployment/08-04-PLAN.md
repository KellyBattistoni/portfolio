This step is the human gate: confirm the CI run is green, then perform the one-time GitHub Pages Settings configuration (research Pitfall 2 — user sites do NOT auto-serve from `gh-pages` and require an explicit Settings switch).
  </what-built>
  <how-to-verify>
    Part A — confirm CI green:
    1. Open `https://github.com/KellyBattistoni/KellyBattistoni.github.io/actions`.
    2. Find the most recent run of "Deploy to GitHub Pages".
    3. Wait for it to complete (expected: ~4–7 minutes — npm ci + playwright install dominate the time).
    4. Confirm every step ends in a green check, especially:
       - "Build" (npm run build)
       - "Lint" (npm run lint)
       - "Wait for preview server" (no SIGTTIN hang — wait-on returned 0 before timeout)
       - "Run Playwright smoke tests" (1 test passed)
       - "Deploy to GitHub Pages" (peaceiris pushed to gh-pages)
    5. If any step is red, STOP and surface the failing step's log. Common failure modes from research:
       - Pitfall 1: wait-on succeeds but playwright times out → confirm `< /dev/null` is in the preview step
       - Pitfall 3: deploy step says "Permission denied" → confirm workflow `permissions:` block has `contents: write`
       - Pitfall 4: lint step fails with `unknown option '--ext'` → fix package.json lint script
       - Pitfall 6: playwright step fails with "Host system is missing dependencies" → confirm `--with-deps` is present

    Part B — confirm gh-pages branch was created:
    1. Visit `https://github.com/KellyBattistoni/KellyBattistoni.github.io/branches`.
    2. Confirm a `gh-pages` branch exists with a single commit (force_orphan: true).

    Part C — one-time GitHub Pages Settings configuration (research Pitfall 2):
    1. Visit `https://github.com/KellyBattistoni/KellyBattistoni.github.io/settings/pages`.
    2. Under "Build and deployment > Source", select `Deploy from a branch`.
    3. Under "Branch", select `gh-pages`, folder `/ (root)`.
    4. Click "Save".
    5. Wait 1–2 minutes. The page will eventually show "Your site is live at https://KellyBattistoni.github.io/".

    Part D — confirm live site loads:
    1. Visit `https://KellyBattistoni.github.io/` in a fresh browser tab (or hard refresh with cache cleared).
    2. Confirm the hero loads with Kelly's name, tagline, and CTA.
    3. Confirm no console errors in DevTools.
    4. Confirm the EN/ES switcher is visible and functional.

    Resume with:
    - "approved" if all four parts pass
    - A description of any failure (which part, which step, what error)

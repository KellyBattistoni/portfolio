Per D-01, the remote URL is exactly `https://github.com/KellyBattistoni/KellyBattistoni.github.io.git` and the remote name is `origin`. Per research Pitfall 3, push must use the GITHUB_TOKEN-compatible HTTPS URL (not SSH) so subsequent CI auth works without PAT setup.

    Commands (run sequentially; stop on first failure and surface the error):
    - `git status` — confirm working tree is clean before mutating refs. If dirty, stop and report.
    - `git branch -m master main` — rename local branch in place. No-op if already on `main`.
    - `git remote add origin https://github.com/KellyBattistoni/KellyBattistoni.github.io.git` — add the origin remote.
    - `git remote -v` — print remotes to confirm both fetch + push lines point at the correct URL.
    - `git push -u origin main` — push and set upstream. If this prompts for credentials, GitHub CLI/Credential Manager handles auth; do not embed any token in the URL.

    Do not run `git push origin --delete master` — there is no remote `master` yet to delete. Do not change the default branch on GitHub via API; the user will set it via Settings > Branches in Task 3.
  </action>

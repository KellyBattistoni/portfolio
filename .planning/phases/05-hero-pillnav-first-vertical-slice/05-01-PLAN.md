    The current LanguageSwitcher has `className="fixed top-6 right-6 z-50 flex gap-4"` hardcoded on its root `<div>`. Phase 5 removes the standalone floating switcher and embeds it inside PillNav and MobileNav. The component must become position-neutral.

    Changes to LanguageSwitcher.tsx:
    1. Add `className?: string` to the function signature: `export function LanguageSwitcher({ className }: { className?: string })`
    2. Replace the hardcoded class string on the root `<div>` with the prop: `className={clsx('flex gap-4', className)}` — this keeps `flex gap-4` as a sensible internal default and allows callers to override positioning.
    3. Keep all other internals exactly as-is: LANGS, handleChange, button rendering, aria-pressed, after: underline classes, accent color. No behavior changes.

    The `clsx` import is already present. Do not add any new imports.

    After this change, `<LanguageSwitcher />` with no prop renders `flex gap-4` only (no fixed position). `<LanguageSwitcher className="flex gap-3" />` renders `flex gap-3 flex gap-4` — which is fine since Tailwind v4 deduplication handles gap conflicts, but to keep it clean, change the default to empty string: `className={clsx(className ?? 'flex gap-4')}` so callers providing a className fully replace the default.

    Final shape of the root div className:
    ```tsx
    className={clsx(className ?? 'flex gap-4')}
    ```

    This means:
    - `<LanguageSwitcher />` → `flex gap-4` (backward-compatible default)
    - `<LanguageSwitcher className="flex gap-3" />` inside PillNav → `flex gap-3`
    - The standalone usage in App.tsx (which will be removed in Plan 04) continues to compile without props
  </action>

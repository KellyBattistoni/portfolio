### 1. Create `src/lib/i18n/index.ts`

This is the single i18n configuration file. It imports all 12 JSON files, registers `LanguageDetector` + `initReactI18next`, and calls `i18n.init(...)` synchronously at module load.

Configuration MUST match the user's locked decisions and RESEARCH.md Pattern 1 exactly:

```typescript
// src/lib/i18n/index.ts
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import LanguageDetector from 'i18next-browser-languagedetector'

import enCommon from '@/locales/en/common.json'
import enHero from '@/locales/en/hero.json'
import enAbout from '@/locales/en/about.json'
import enProjects from '@/locales/en/projects.json'
import enStack from '@/locales/en/stack.json'
import enContact from '@/locales/en/contact.json'
import esCommon from '@/locales/es/common.json'
import esHero from '@/locales/es/hero.json'
import esAbout from '@/locales/es/about.json'
import esProjects from '@/locales/es/projects.json'
import esStack from '@/locales/es/stack.json'
import esContact from '@/locales/es/contact.json'

export const defaultNS = 'common' as const

export const resources = {
  en: {
    common: enCommon,
    hero: enHero,
    about: enAbout,
    projects: enProjects,
    stack: enStack,
    contact: enContact,
  },
  es: {
    common: esCommon,
    hero: esHero,
    about: esAbout,
    projects: esProjects,
    stack: esStack,
    contact: esContact,
  },
} as const

void i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources,
    fallbackLng: 'en',
    defaultNS,
    ns: ['common', 'hero', 'about', 'projects', 'stack', 'contact'],
    supportedLngs: ['en', 'es'],
    nonExplicitSupportedLngs: true,
    interpolation: {
      escapeValue: false,
    },
    detection: {
      order: ['localStorage', 'navigator'],
      lookupLocalStorage: 'kbv-lang',
      caches: ['localStorage'],
    },
    parseMissingKeyHandler: (key, _defaultValue, options) =>
      `${options?.ns ?? 'unknown'}:${key}`,
    returnNull: false,
    react: {
      useSuspense: false,
    },
  })

export default i18n
```

CRITICAL details — do NOT deviate:
- `resources` and `defaultNS` MUST be marked `as const` (RESEARCH.md Pitfall 6 — without it, type augmentation produces `(key: string) => string` instead of typed keys).
- `caches: ['localStorage']` is REQUIRED for `kbv-lang` to persist (RESEARCH.md Pitfall 2 — `lookupLocalStorage` alone only READS, doesn't write).
- `nonExplicitSupportedLngs: true` makes `es-AR`, `es-MX`, `es-419` all resolve to `es` (success criterion 4).
- `parseMissingKeyHandler` returns the key path so missing keys render visibly (e.g. `hero:heading.title`) per CONTEXT.md "missing key fallback" decision.
- `useSuspense: false` because resources are sync-ready (RESEARCH.md "No Suspense needed").
- `void` prefix on the chained `.init(...)` call avoids the `no-floating-promises` lint error (RESEARCH.md Pitfall 5).
- Use `import LanguageDetector from 'i18next-browser-languagedetector'` (default import) — verbatimModuleSyntax does NOT block value imports, only type-only ones.

### 2. Create `src/@types/i18next.d.ts`

Module augmentation for typed `t()` keys. This file augments the `'i18next'` package (NOT `'react-i18next'`):

```typescript
// src/@types/i18next.d.ts
import 'i18next'
import type { defaultNS, resources } from '@/lib/i18n'

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: typeof defaultNS
    resources: (typeof resources)['en']
    returnNull: false
  }
}
```

The `import type` on `defaultNS, resources` is required by `verbatimModuleSyntax: true` (RESEARCH.md Pitfall 4). The bare `import 'i18next'` is a side-effect import that loads the module so `declare module 'i18next'` augments it.

This file is auto-included because tsconfig.app.json has `"include": ["src"]`. Confirm by inspecting tsconfig.app.json — do NOT add explicit `"types"` or `"typeRoots"` entries.

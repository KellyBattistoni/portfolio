  <how-to-verify>
### Verification step 1 — Initial render + switcher visible
1. Open a fresh browser window in **Incognito / Private mode** (so localStorage starts empty).
2. Open DevTools (F12). Switch to **Application -> Local Storage -> http://localhost:5173** and confirm there is NO `kbv-lang` key.
3. Visit the dev server URL (default `http://localhost:5173/`).
4. Expected:
   - The page shows: a large title ("Kelly Battistoni"), a tagline paragraph, and a CTA button — all visible as real readable strings.
   - **No key paths** like `hero:heading.title` appear anywhere in the UI. If they do, the init file did not run or a JSON key is missing.
   - In the top-right of the viewport, you see two text labels: `EN` and `ES`. One of them has an orange underline (`#FF4500`).
5. Check Application -> Local Storage again — `kbv-lang` should now exist with value `"en"` or `"es"`. The detector wrote it on first paint.
6. Check Elements -> `<html>` tag — `lang` attribute should be `"en"` or `"es"` matching the active label in the switcher.

### Verification step 2 — Toggle re-renders all visible strings
1. Click the OTHER language tab (e.g. if EN is active, click ES).
2. Expected:
   - The orange underline animates (slides) from the previous tab to the clicked tab over ~300ms.
   - The title, tagline, and CTA all re-render in the new language — instantly, no page reload.
   - Application -> Local Storage `kbv-lang` value updates to the new code.
   - Elements `<html lang>` updates to the new code.
3. Click back to the first language. Same behavior in reverse.
4. **No key paths in the visible UI in either state.**

### Verification step 3 — Persistence on reload
1. Choose ES (or whichever is not currently active).
2. Hard-refresh the page (Ctrl+Shift+R / Cmd+Shift+R).
3. Expected:
   - Page restores in the language you chose, NOT the browser default.
   - Application -> Local Storage shows `kbv-lang` still set to your chosen language.
   - `<html lang>` matches.

### Verification step 4 — First-visit auto-detection
1. In DevTools -> Application -> Local Storage, delete the `kbv-lang` key entirely.
2. Hard-refresh.
3. Expected:
   - The page renders in the language matching your browser preference (typically ES if your browser is Spanish, EN otherwise).
   - `kbv-lang` is re-written by the detector to match.
4. If you want to test the other branch: in Chrome -> Settings -> Languages -> temporarily set Spanish at the top -> restart the browser -> hard refresh with cleared localStorage -> page should render in ES even if your OS is English.

### Verification step 5 — All 12 JSON files load (defensive)
1. Open React DevTools and locate any component using `useTranslation` (e.g. `App` or `LanguageSwitcher`).
2. Inspect the hook state -> `i18n.options.resources` should contain `en` and `es`, each with all 6 namespace keys (`common`, `hero`, `about`, `projects`, `stack`, `contact`).
3. Confirm the `about`, `projects`, `stack`, `contact` namespaces each contain a `_placeholder` key (per Plan 02-01 Task 2) — this proves they loaded even though no UI renders from them yet.

  <name>Task 1: Create useLocalizeDocumentAttributes hook</name>
  <files>src/hooks/useLocalizeDocumentAttributes.ts</files>
  <action>
Create the hook that mirrors `i18n.resolvedLanguage` to `document.documentElement.lang`. The `htmlTag` detector option only READS the existing `<html lang>` — it does NOT write back (RESEARCH.md Pitfall 1). So we write it ourselves.

```typescript
// src/hooks/useLocalizeDocumentAttributes.ts
import { useEffect } from 'react'
import { useTranslation } from 'react-i18next'

/**
 * Syncs document.documentElement.lang to i18n.resolvedLanguage on mount
 * and whenever the active language changes.
 *
 * Why: i18next-browser-languagedetector's `htmlTag` option only READS the
 * pre-existing `<html lang>`; it never writes back. Without this hook the
 * <html> tag stays "en" forever, breaking SEO/AT semantics and failing
 * Phase 2 success criterion 3.
 */
export function useLocalizeDocumentAttributes(): void {
  const { i18n } = useTranslation()

  useEffect(() => {
    if (i18n.resolvedLanguage) {
      document.documentElement.lang = i18n.resolvedLanguage
    }
  }, [i18n.resolvedLanguage])
}
```

CRITICAL details:
- Use `i18n.resolvedLanguage` (post-fallback, canonical: `'es'`), NOT `i18n.language` (may carry `'es-AR'`) — RESEARCH.md Pitfall under "Common Operation" / Pattern 3.
- Return type explicitly `void` — keeps the hook's contract clear (no exposed state).
- Effect depends on `i18n.resolvedLanguage` so it re-fires on every successful language change. react-i18next triggers a re-render on `languageChanged` (default `bindI18n` config), which updates `i18n.resolvedLanguage` and re-runs this effect.
- Do NOT call `useEffect` on the raw `i18n.language` (lint may insist either way; we want the canonical resolved value regardless).

No SSR guard needed — Vite ships a CSR-only build, `document` is always defined when this hook runs.

```tsx
// src/components/i18n/LanguageSwitcher.tsx
import { useTranslation } from 'react-i18next'
import { clsx } from 'clsx'

const LANGS = ['en', 'es'] as const
type Lang = (typeof LANGS)[number]

/**
 * EN/ES language switcher with sliding-underline active state.
 *
 * - Two <button> elements inside a <div role="group">
 * - Active button: `aria-pressed="true"` + visible accent underline
 * - Inactive button: underline scaled to 0 (Tailwind transition)
 * - Calls `i18n.changeLanguage(lng)` on click; void-prefixed to satisfy
 *   no-floating-promises (react-i18next re-renders on languageChanged event)
 *
 * Positioned fixed top-right for Phase 2 only. Phase 5 imports this same
 * component into PillNav — DO NOT couple positioning to a parent here.
 *
 * Wrapped by AnimationErrorBoundary in App.tsx (per Phase 1 policy: anything
 * with a transition is bounded).
 */
export function LanguageSwitcher() {
  const { i18n, t } = useTranslation('common')
  const current = (i18n.resolvedLanguage as Lang | undefined) ?? 'en'

  const handleChange = (lng: Lang) => {
    if (lng === current) return
    void i18n.changeLanguage(lng)
  }

  return (
    <div
      role="group"
      aria-label={t('switcher.ariaLabel')}
      className="fixed top-6 right-6 z-50 flex gap-4"
    >
      {LANGS.map((lng) => {
        const isActive = lng === current
        return (
          <button
            key={lng}
            type="button"
            onClick={() => handleChange(lng)}
            aria-pressed={isActive}
            className={clsx(
              'relative text-sm font-medium uppercase tracking-wider',
              'text-white/80 hover:text-white transition-colors',
              'after:absolute after:left-0 after:right-0 after:-bottom-1 after:h-px',
              'after:bg-[#FF4500] after:origin-left after:transition-transform after:duration-300',
              isActive ? 'after:scale-x-100 text-white' : 'after:scale-x-0',
            )}
          >
            {t(`switcher.${lng}` as const)}
          </button>
        )
      })}
    </div>
  )
}
```

CRITICAL details:
- `i18n.resolvedLanguage` (not `i18n.language`) for the active-state comparison — handles `es-AR` → `es` correctly.
- `void i18n.changeLanguage(lng)` — no-floating-promises lint error otherwise (RESEARCH.md Pitfall 5).
- `aria-pressed` on each button + `role="group"` on the wrapper for AT semantics.
- Tailwind `after:` pseudo-element creates the underline; `scale-x-0`/`scale-x-100` with `origin-left` produces the slide-in effect on language change (no JS animation needed for the underline itself).
- Accent color `#FF4500` is the Phase 1 brand token, applied via arbitrary-value Tailwind class `after:bg-[#FF4500]` (NOT a custom CSS class). Phase 1 ships the token in `@theme` so when CSS variables are confirmed working we could swap to `after:bg-(--color-accent)` — but for Phase 2 use the explicit hex per CONTEXT.md "accent underline (#FF4500 or similar)".
- Button label comes from translation: `t('switcher.en')` returns `"EN"` in both locales (defined in 02-01 common.json).
- Positioning is hard-coded `fixed top-6 right-6 z-50` per CONTEXT.md temporary placement. Phase 5 will REMOVE these classes when moving into PillNav — DO NOT add a `className` prop here, the temporary positioning belongs in the component.
- Component does NOT include the "text fade on language swap" transition for the page content — that ships in Phase 5 per CONTEXT.md ("Language-switch transition... handled in Phase 5's animation work"). Phase 2 only needs the underline transition.
- DO NOT add `LANGS` to translation files — it's a literal `['en','es']` and shouldn't be translatable.

DO NOT import `i18n` directly from `@/lib/i18n`. Use `useTranslation('common')` and call `i18n.changeLanguage` on the hook-returned instance. This keeps the component decoupled from the singleton and matches Phase 5's expected import shape.
